# IRS AI — Infrastructure Image Analysis Service

AI microservice for the **Infrastructure Reporting System (IRS)**, my graduation project at the
Egyptian E-Learning University (graded *Excellent*).

When a citizen reports damaged infrastructure, they upload one or more photos. This service sends the
photos to a vision language model, which returns:

- a **category** for the issue (for example, *Potholes and Road Cracks*), and
- a short **description** of the damage (3–5 sentences).

The IRS back end (ASP.NET Core, .NET 9) uses the result to pre-fill the report, so citizens don't
have to classify the problem themselves and authorities get consistent, searchable categories.

> Main API repository: [InfrastructureReportingSystem](https://github.com/MostafaAbuHamed/InfrastructureReportingSystem/tree/Dev)

## How it fits in

```
Angular client ──► ASP.NET Core API ──► IRS AI (this service) ──► Vision LLM
                   (typed HttpClient)    FastAPI on Hugging Face    (NVIDIA NIM)
```

The .NET API calls `POST /classify-image` through a typed `HttpClient`. If this service is down it
returns `503`, and the API shows the user a friendly "try again later" message instead of failing
the whole report.

## Tech stack

- **Python 3.11** and **FastAPI**
- **Llama 3.2 11B Vision Instruct** through the NVIDIA NIM API (OpenAI-compatible client)
- **Docker**, deployed to **Hugging Face Spaces**
- **GitHub Actions** for automatic deployment on every push to `main`

### Model history

The service started with **Google Gemini** (later Gemini 2.5 Flash Lite). I moved it to
**Llama 3.2 Vision on NVIDIA NIM** to get more reliable availability during the project demo.
Because the model sits behind one endpoint, the .NET API didn't need any changes when the model
changed.

## API

### `POST /classify-image`

Request: `multipart/form-data` with one or more files in the `images` field.
Supported types: JPEG, PNG, WebP, GIF, HEIC, HEIF.

```bash
curl -X POST http://localhost:7860/classify-image \
  -F "images=@pothole-1.jpg" \
  -F "images=@pothole-2.jpg"
```

Response `200 OK`:

```json
{
  "category": "Potholes and Road Cracks",
  "description": "The road surface shows a large pothole with cracked edges in the right lane. Loose asphalt is scattered around it, and water has collected at the bottom. The damage is a hazard for vehicles and should be repaired soon."
}
```

**Categories:** Damaged concrete structures · Damaged Electrical Poles · Damaged Road Signs ·
Dead Animals Pollution · Fallen Trees · Garbage · Graffitti · Illegal Parking ·
Potholes and Road Cracks · Water leak

**Errors**

| Status | When |
| ------ | ---- |
| `400`  | A file isn't a supported image type |
| `500`  | The model returned an empty response or invalid JSON |
| `503`  | The model provider couldn't be reached |

Interactive docs are available at `/docs` (generated by FastAPI).

## Design notes

- **Structured output from an LLM:** the prompt restricts the model to a fixed category list and a
  raw JSON object. The service also strips any Markdown code fences before parsing, and returns
  `500` if the output still isn't valid JSON, so the API never receives a malformed result.
- **Low temperature (0.1)** keeps classifications consistent for similar photos.
- **Multiple images per report** are sent in a single request, so the model sees the whole scene.

## Run locally

1. Create a `.env` file:

   ```env
   NVIDIA_API_KEY=your-key-here
   ```

2. Run with Python:

   ```bash
   pip install -r requirements.txt
   uvicorn main:app --host 0.0.0.0 --port 7860
   ```

   Or with Docker:

   ```bash
   docker build -t irs-ai .
   docker run -p 7860:7860 --env-file .env irs-ai
   ```

3. Open <http://localhost:7860/docs>.

## Deployment

Every push to `main` triggers [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml), which
pushes the repository to the Hugging Face Space. The Space builds the `Dockerfile` and serves the
app on port `7860`. The NVIDIA API key is stored as a Space secret, and the Hugging Face token as a
GitHub Actions secret.
